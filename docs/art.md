# 美术管线（v0.1）

> 本文说明「当前美术怎么来的、怎么改、以后怎么换成真素材」。
> 口径与 `AGENTS.md` 第 4 节「数据驱动原则」一致：**图和数值一样，都是配置，不是代码**。

## 0. 现状：美术是"程序化像素图 + 程序化插画"

本机（以及当时的环境）无法从外部下载素材，所以 v0.1 的美术**没有一张 PNG 文件**，全部由数据 + 代码在启动时编译出来：

| 内容 | 数据 / 代码 | 编译 |
|---|---|---|
| 英雄、怪物、Boss、召唤物、资源球、子弹、碎块 | `data/sprites.json`（字符矩阵） | `src/assets/pixel.ts` → `compileRows()` |
| **战斗背景（一张完整的夜景插画）** | `src/assets/arena.ts`（Canvas 2D 分层绘制） | `compileCanvas()` → 单张 1280×720 贴图 |
| 背景动态层（火焰 / 余烬 / 浮尘 / 薄雾 / 法阵呼吸） | `src/assets/ambience.ts` | Phaser 粒子 + 补间 |
| 实体显示缩放 / 投影 / 压扁 / 翻转 | `data/visuals.json` | `src/assets/visuals.ts` |

好处：零二进制资产、可 diff、可 code review、启动零网络请求、包体最小。
代价：背景是"风格化插画"而不是手绘原画；角色上限在"能看"这一档。

## 0.1 背景是怎么画出来的（`src/assets/arena.ts`）

绘制顺序（越靠后越在上层）：

1. **夜色底**：深蓝黑垂直渐变（`#080d14 → #03050a`）。
2. **大块色域**：`soft-light` 的青 / 紫 / 墨绿软斑，把整张图统一成同一氛围。
3. **阶梯圆形石台**：三层同心圆（r = 520 / 404 / 292），每层有投影、径向渐变台面、放射石缝、同心石缝、上亮下暗的倒角、以及 2000+ 颗石面颗粒。
4. **污渍 / 苔藓 / 旧血痕**：22 团软边色块。
5. **裂纹**：6 条抖动折线，暗芯 + 1px 错位亮边（凿刻感）。
6. **中央法阵**：三重同心环 + 48 根符文刻度 + 六芒星 + 中心圆盘（透明度都很低，不能盖住角色）。
7. **四角巨石堆**：平滑贝塞尔轮廓的圆润石块，投影受光分离。
8. **火盆**：石台 + 金属盆 + 炭块 + 缝隙火光（火焰是动态粒子，不在贴图里）。
9. **光照**：月光用 `soft-light`（保对比），火盆近处用 `screen` 热点，中央法阵冷光。
10. **四边压暗 + 暗角 + 14000 颗胶片颗粒**。

关键经验（改这张图时别踩）：

- **光照层叠加方式很重要**：全用 `screen` 会把对比压平，整张图变"灰汤"。大面积用 `soft-light` / `overlay`，只有火盆近处用 `screen`。
- **相邻石板必须有明度差**，否则一大片石面会糊成一块。每个元素都要有自己的随机色调。
- **地面要暗、光池要亮**，靠对比出"画面感"；中等亮度铺满全屏最像程序占位图。

生成耗时约 **8–10ms**（一次，在 Boot 里），不会影响开屏。

## 0.2 想换成真图？

把任意一张 1280×720 的插画放到 **`src/assets/arena.png`**（文件名以 `arena` 开头即可，如 `arena-castle.png`），重启后就会直接用它当战斗背景，程序化绘制自动让位。

实现是 `BootScene` 里的 `import.meta.glob('../assets/arena*.png')`：没放图时**不会产生任何网络请求**（所以控制台不会出现 404）。

换成真图后建议同时调 `data/visuals.json` 里的 `scale`，让角色和背景比例协调。

## 0.3 快速看背景 / 看角色

```bash
npm run dev
```

- `http://127.0.0.1:5173/preview.html` — **只渲染背景**，不启动 Phaser、不依赖 `/data` 配置（并行改玩法时也能单独验收美术）。标题栏会显示绘制耗时。
- `http://127.0.0.1:5173/preview.html?sheet=1` — **姿势总览**：所有角色 × 4 个姿势帧（基础 / 行走 / 受击 / 死亡）。
- `node tools/arena-shot.mjs` — 截背景到 `.shots/40-arena.png`。
- `node tools/arena-shot.mjs sheet` — 截姿势总览到 `.shots/41-poses.png`。
- `node tools/sprite-sheet.mjs` — 6 倍放大所有角色基础贴图到 `.shots/sprites.png`，行宽不一致会报警。
- `node tools/art.mjs` — 截 Prep / 战斗 / 召唤三张实际画面到 `.shots/`。

## 0.4 行走 / 受击 / 死亡帧（`src/assets/poses.ts`）

每个会动的单位（英雄、怪物、召唤物）在编译时会自动多出 3 张贴图：

| 贴图 key | 用途 | 生成方式 |
|---|---|---|
| `<key>-walk1` | 行走第 2 帧（与基础帧交替） | 下半身向两侧张开，读作迈步 |
| `<key>-hurt` | 受击帧 | 横向向中心收 1px + 整体下移 1px，配合闪白 |
| `<key>-death` | 死亡帧 | 垂直压扁成"塌下去"的一坨，配淡化 + 碎块 |

- 切换频率在 `data/visuals.json` 的 `walk_ms`（每个单位可以不同：疾行者 130ms、重装 280ms、Boss 360ms）。
- **想手画覆盖**：在 `data/sprites.json` 对应条目里加同名 `walk` / `hurt` / `death` 行数组即可，编译时优先用手画的。
- `bob`（垂直压扁）现在只保留 0.02–0.05 的余动，**它不再是"走路"的替代品**。
- 消耗类贴图（bullet / pickup / shard）不生成姿势帧。

## 1. 怎么改一张图

1. 打开 `data/sprites.json`，找到对应条目（`hero` / `grunt` / `runner` / `brute` / `summon_economy` / …）。
2. 改字符行。每个字符是一个像素，`.` 为透明；**同一张图所有行必须等宽**。
3. 颜色不用写死：字符角色由实体主色派生（见文件里的 `_comment`）。

| 字符 | 含义 | 来源 |
|---|---|---|
| `o` | 描边 | 主色压暗 80% |
| `d` | 暗部 | 主色压暗 42% |
| `b` | 主色 | `data/enemies.json` 等里的 `color` |
| `l` | 亮部 | 主色提亮 30% |
| `h` | 高光 | 主色提亮 62% |
| `w` / `k` | 眼白 / 瞳孔 | 固定 |
| `a` | 强调色 | 可被条目里的 `palette` 覆盖 |

想给某张图固定颜色，就在该条目加 `"palette": { "a": "#ffd166" }`。

4. 改完跑一次预览图（不需要浏览器）：

```bash
node tools/sprite-sheet.mjs
```

产物 `.shots/sprites.png` 是 6 倍放大的拼版图，行宽不一致会在控制台报警。

## 2. 怎么改大小/手感

`data/visuals.json`，每个贴图 key 一段：

```json
"enemy-grunt": { "scale": 2.5, "shadow": 0, "bob": 0.08, "flip": true, "rotate": false }
```

| 字段 | 作用 |
|---|---|
| `scale` | 显示缩放。整数或 `.5` 最稳 |
| `shadow` | 脚下椭圆投影宽度（px），0 = 不画 |
| `bob` | 行走时垂直压扁幅度（0–0.2） |
| `flip` | 是否按水平速度左右翻转 |
| `rotate` | 是否让朝向跟随速度（子弹用） |

**碰撞半径不在这里**，仍在 `enemies.json` / `summons.json` / `heroes.json` 的 `radius`。
显示大小和碰撞大小是两件事：调 `scale` 不会让怪更难打，反之亦然。

## 3. 以后换成真素材（图集）要动哪里

只有一处接缝：`src/assets/sprites.ts` 的 `buildActorTextures()`。

1. 素材放进 `public/assets/`（Vite 会把它映射到 `/assets/`）。
2. 在 `BootScene.preload()` 里 `this.load.atlas('actors', 'assets/actors.png', 'assets/actors.json')`。
3. 在 `buildActorTextures()` 里，贴图 key 已存在就跳过编译 —— 现在的 `compileRows()` 第一行就是 `if (scene.textures.exists(key)) return;`，所以**加载图集后自动走图集，不需要删代码**。
4. 若图集里帧名和运行时 key 不一致，在 `data/visuals.json` 补 `atlas` / `frame` 字段做映射（当前版本还没读这两个字段，需要时再加）。

也就是说：**换美术不需要改 `BattleScene`**，这是刻意留的接缝。

## 4. 授权记录

v0.1 的贴图全部是本仓库自己生成的，无第三方素材，无授权义务。

以后引入外部素材（Kenney / OpenGameArt / itch.io 等）时，**必须在这里补一行**：来源链接、作者、授权（CC0 / CC-BY / OGA-BY）、引入日期、用在哪。

| 日期 | 素材 | 来源 | 授权 | 用途 |
|---|---|---|---|---|
| — | 全部程序化生成 | 本仓库 | 自有 | 全部 |

注意：CC-BY / OGA-BY 要求在游戏内或说明文件里署名，CC0 不要求但建议记录。

## 5. 已知不足（下一步）

- 行走只有 **2 帧**（基础 + `-walk1`）；4/6 帧会更顺，但需要手画覆盖。
- 没有方向性美术（俯视追逐，靠 `flipX` 翻转），只有左右两个朝向。
- 受击 / 死亡帧是**程序化派生**的（收缩 / 压扁），不是手绘专属动作。
- 召唤物与怪物的剪影差异靠颜色 + 有无角，不够强。
- 手机端：已用 `pixelArt` + `autoRound` + CSS `image-rendering: pixelated` + 文字 2 倍纹理密度
  解决"非整数缩放发糊"，代价是像素边缘在大幅缩小时会有一点锯齿（画布 buf 仍是 1280×720）。
- 想要真正往"商业像素游戏"走，见 `docs/art-prompts.md`（路线 B：AI 出图 + 我接入）。
